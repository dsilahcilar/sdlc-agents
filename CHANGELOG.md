## [Unreleased]

### Breaking Changes

- **Stack files refactored**: All `agents/skills/stacks/*.md` files changed from verbose guides to concise specification format
  - Removed: Tool installation instructions, detailed examples, best practices  
  - Kept: Detection rules, command tables, minimal rule templates
  - See `docs/MIGRATION_GUIDE.md` for migration details

- **Harness templates are now placeholders**: Templates in `agents/templates/harness/` no longer contain working code
  - Scripts must be generated by initializer agent
  - Projects using old templates must regenerate scripts via `@initializer-agent`

### Added

- **Version 2** in `v2/`, beside version 1 and without changing how version 1 installs. See `v2/README.md`.
  - `v2/gate/handover_gate.py`: a handover gate that works out what a change owes (which kinds of test, a security review, an architect pass, a human approval) and where it goes next. Path rules decide what they can, an optional judge answers one yes/no question for the rest, and a judge that gives no answer takes the stricter route. Rules are data in `rules.json`. Standard library only, with tests.
  - `v2/roles/reviewer.md` and `v2/roles/architect.md`: two short agent files in place of the seven.
  - `v2/templates/`: the brief, a pull request template, the delivery contract for `CLAUDE.md`, starter rules, and one short lessons file per reviewing role.
  - `v2/install.sh`: copies files into a repository and links nothing.
  - `v2/docs/`: the gate design and rules reference, how learnings are kept, and a map from version 1.
  - After a trial on past pull requests: the reviewer has a bar for what blocks and a `worth_fixing` list for the rest, and reports findings that rest on code it cannot read as questions. An evidence rule can let a reported run count (`run_counts`, answered by a `Ran <item>: ...` line). The starter rules gain `script-run` for deploy and operations scripts. A diff too large for one question is asked about in up to four parts before it counts as owed. `--pull-request-from` replaces `--waivers-from`, which still works.

- **Kotlin support**: Added `agents/skills/stacks/kotlin.md` with full Gradle/Maven support
  - Detection for `build.gradle.kts` with `*.kt` files
  - Support for Ktlint, Detekt, Kover, ArchUnit, Konsist

- **Skill directives**: Agents now support directive syntax in user prompts
  - `#SkillName` - Force-load skill
  - `#Skill1,Skill2` - Load multiple skills  
  - `!SkillName` - Exclude skill
  - `#only:Skills` - Use only listed skills

- **Harness specification**: Added `agents/skills/harness-spec.md` defining output contract for generated scripts

- **Migration guide**: Added `docs/MIGRATION_GUIDE.md` for projects migrating from old templates

### Removed

- A lesson from one project that had ended up in the shared templates `agents/templates/extensions/planning-agent/learned-patterns.md` and `agents/templates/extensions/architect-agent/learned-patterns.md`. The templates are back to placeholders.

### Improved

- **Stack detection**: Enhanced Kotlin vs Java detection logic with priority ordering
- **Code reduction**: Removed ~1,100 lines of redundant documentation from stack files
- **Maintainability**: Clearer separation between specs (for LLMs) and guides (for humans)

### Changed

- **Renamed `.agents/` to `.sdlc-agents/`**: More specific directory name to avoid conflicts with other tools that might use the generic `.agents` directory name. All install scripts, agent files, and documentation updated to use `.sdlc-agents/` consistently.

### Added

- **GitHub Copilot Agent Support**: Proper support for custom agents in GitHub Copilot
  - Creates `.github/agents/*.agent.md` files for each agent
  - Each agent file has YAML frontmatter for GitHub Copilot discovery
  - Agents are accessible via VS Code UI agent picker
  - Automatic `.gitignore` update to exclude `.sdlc-agents/` directory
- **Multi-Assistant Support**: SDLC Agents now works with 5 AI coding assistants
  - GitHub Copilot
  - Claude Code
  - Cursor  
  - Windsurf
  - Aider
- **Unified Install Script**: Single `./install.sh` with tool selection flags
  - `--ghcp`, `--claude`, `--cursor`, `--windsurf`, `--aider`
  - `--all` to install for all tools
  - `--copy` mode for Windows compatibility
- **Tool-Specific Adapters**: Each tool gets its own configuration
  - Tool configs in `tools/<tool>/`
  - Shared agent instructions in `agents/`
- **Multi-Assistant Documentation**: New `docs/MULTI_ASSISTANT_SUPPORT.md`
  - Tool selection guide
  - Multi-tool usage patterns
  - Tool-specific troubleshooting

### Changed

- **GitHub Copilot installation structure**: 
  - Now creates `.github/agents/` directory with individual `.agent.md` files
  - Uses `.sdlc-agents/` (hidden directory) instead of `agents/` for symlink
  - Automatically updates `.gitignore` to exclude `.sdlc-agents/`
  - Removed `copilot-instructions.md` (not needed)
- **Agent files are now tool-agnostic**: Removed YAML frontmatter from all `agents/*.md` files
- **Updated documentation**: `AGENT_ARCHITECTURE.md` and `COMPARISON_WITH_SPEC_KIT.md` updated to reflect multi-tool support
- **Simplified agent path handling**: 
  - All agent files now use hardcoded `.sdlc-agents/` path instead of dynamic `find` command
  - Replaced complex `SDLC_AGENTS=$(dirname "$(find . -name "initializer-agent.md" ...)")` with simple `SDLC_AGENTS=".sdlc-agents"`
  - Updated all `$SDLC_AGENTS` references in agent files to use `.sdlc-agents/` directly
  - More reliable and faster path resolution across all providers

### Migration Guide

If you were using SDLC Agents with GitHub Copilot before:

1. **Re-run the installer** to get the new `.github/agents/` structure:
   ```bash
   ./install.sh --ghcp --target /path/to/your/project
   ```

2. **Your existing content is preserved** — the installer only updates configuration files

3. **New usage**: In VS Code, open GitHub Copilot Chat and use the agent picker:
   - Click the **@ icon** in the chat input
   - Select an agent from the dropdown (e.g., planning-agent, coding-agent)
   - Type your request

4. **Clean up old structure** (optional):
   - Remove old `agents/` symlink if it exists: `rm agents`
   - The new `.sdlc-agents/` directory is hidden and excluded from git

5. **Optional**: Install support for additional tools with `--all` or specific tool flags
